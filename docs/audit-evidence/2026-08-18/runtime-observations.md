# 《老虎机塔防 / 九宫防线》运行体检证据

> 日期：2026-08-18  
> 对象：`geminicode.html`  
> 方式：仅绑定 `127.0.0.1:8124` 的 Python 静态服务器 + Playwright Chromium 自动化  
> 完成边界：验证 Chromium 桌面、移动触摸模拟与多个视口；未验证 iOS Safari、Android Chrome 真机、Firefox、WebKit 和公网环境。

## 1. 环境与入口

- `http://127.0.0.1:8124/geminicode.html`：HTTP 200，响应 29055 字节。
- `http://127.0.0.1:8124/`：HTTP 200，但返回目录列表，不会自动进入游戏。
- 页面标题：`《九宫防线》 - 动态配方优化原型`。
- 初始化后生成 9 个构筑格、9 个老虎机格，AP 为 50。
- 页面网络请求仅见本地 `geminicode.html`，未观察到外部资源或 API 请求。
- 首次打开记录到 1 条 `favicon.ico` 404；重新加载后的控制台为 0 错误、0 警告。该 404 不阻断玩法，但属于发布元数据缺失。

## 2. 桌面运行结果

### 2.1 自动合成

步骤：点击「一键注入配方」，等待 900ms。

结果：

- 棋盘从短弓塔 + 火盆变成 1 个重型火箭塔；
- 日志出现「自动合成成功」；
- 当时战场敌人被合成特攻清空；
- 该流程通过。

### 2.2 同名升星

步骤：通过体检状态注入两个 0 星短弓塔；使用真实桌面拖拽把第一个拖到第二个。

结果：

- 源格清空；
- 目标短弓塔变为 1 星；
- 日志出现「升星」；
- `timeScale` 恢复为 1；
- 桌面拖拽升星通过。

### 2.3 战术技能

步骤：注入一个 300 HP 普通敌人；真实拖拽「毁灭打击」到战场。

结果：

- 技能次数从 1 变成 0，界面同步；
- 日志出现释放记录；
- 敌人受到全屏伤害并随后被已有火力击杀；
- `timeScale` 恢复为 1；
- 桌面技能拖放通过。

### 2.4 一次正常老虎机抽取

步骤：点击老虎机，点击「消耗 10 AP 抽卡」，等待动画结束。

结果：

- AP 从 50 降至 40，主界面和弹层同步；
- 中奖格增加 `.win` 状态；
- 抽取按钮恢复可用；
- 奖励建筑进入棋盘；
- **问题**：`modal-result` 始终停留在「等待拉杆...」，没有展示中奖、未中奖、保底或奖励结果。

### 2.5 连续失败保底（固定序列）

说明：为排除随机性，体检在页面运行时暂时替换抽取函数，提供两轮固定无中奖序列；测试后恢复原函数。此操作没有修改磁盘文件。

结果：

- 第一轮无中奖：AP 获得 3 点返还，`consecutiveFails=1`；
- 第二轮无中奖：触发配方保底，直接获得短弓塔，计数清零；
- 日志正确记录保底；
- `modal-result` 仍未更新；
- 保底核心逻辑通过，结果反馈不完整。

### 2.6 满棋盘奖励（固定序列）

说明：运行时填满 9 个格子并固定抽出短弓塔，测试后恢复抽取函数。

结果：

- 棋盘保持 9 个建筑；
- AP 从 50 增至 55；
- 日志出现「自动换取 5 AP」；
- 满棋盘兑换逻辑通过。

## 3. 已复现的阻断缺陷

### 3.1 普通敌人漏怪没有任何后果

可重复场景：把普通敌人放到战场底线之外，等待主循环处理。

观察：

- 敌人从数组和 DOM 删除；
- AP 40 → 40；
- 日志数量 4 → 4；
- 页面没有基地生命、失败计数、结算或提示变化。

结论：普通漏怪只有静默删除，不构成塔防的失败压力。

### 3.2 Boss 漏怪后永久停机

可重复场景：`bossProgress=200` 时让 Boss 越过底线，随后分别等待 250ms、2 秒和正常速度下额外 3 秒。

观察：

- Boss 从敌人数组删除；
- `bossProgress` 始终保持 200；
- `spawnTimer` 保持 0.15；
- 后续敌人数量始终为 0；
- 关闭老虎机、恢复 `timeScale=1` 后仍不再刷新敌人。

结论：Boss 漏怪会让战斗永久停止，是 P0 阻断缺陷。

### 3.3 没有单局结束闭环

真实运行和静态代码均未观察到：基地生命、胜利、失败、结算、重开、下一局、波次完成。当前页面只能无限运行，或在 Boss 漏怪后停机。

## 4. 移动与尺寸验证

### 4.1 触摸拖拽失败

在 Chromium 新建 `hasTouch=true`、`isMobile=true`、390×844 的移动上下文：

1. 注入两个相邻的 0 星短弓塔；
2. 通过 Chrome DevTools Protocol 发送真实 touchStart → touchMove → touchEnd；
3. `navigator.maxTouchPoints=1`、`(pointer:fine)=false`，确认处于触摸环境；
4. 操作后两个建筑仍原位且均为 0 星。

结论：当前依赖 HTML Drag and Drop 的核心交互不能在模拟触摸环境完成；与任务宪法要求的 Pointer Events 及设计文档的移动端目标冲突。iOS/Android 真机仍需人工复验，但不能把当前结果视为移动端可用。

### 4.2 视口布局

| 视口 | 观察 |
|---|---|
| 1440×900 | 页面无滚动溢出，桌面结构完整；战场和九宫格可见。 |
| 320×568 | 页面尺寸无滚动溢出，但九宫格底部恰好贴到视口底边；按钮文字明显换行，日志横向被截断；没有底部安全区余量。 |
| 375×667 | 九宫格底部恰好等于 667px，按钮文字换行；没有底部安全区余量。 |
| 390×844 | 九宫格底部约 815.8px，尚有约 28px 空间；按钮仍换行。 |
| 844×390 横屏 | 战场高度仅 61px，几乎失去可玩空间；九宫格占满剩余高度。横屏不具备可玩性。 |

未发现 CSS 媒体查询或 `safe-area-inset-*`。因此这些视口只是固定尺寸硬塞进页面，不是正式响应式适配。

## 5. 有界性能观察

重新加载干净状态后进行 10 秒 `requestAnimationFrame` 观察：

- 采样时长：10015.7ms；
- 帧数：600；
- 平均约 60 FPS；
- DOM 节点：70 → 70；
- 结束时敌人 11、子弹 0、Boss 进度约 99.15、AP 50。

结论：在当前桌面 Chromium、无塔射击的短时场景中没有观察到帧率或 DOM 持续增长问题。该数据不能代表有大量子弹、长时间运行、低端手机或真机性能。

页面切到另一标签 3 秒再恢复时未抛出错误；但采样发生时 Boss 流程已经进入 200 状态，因此不能据此证明后台恢复逻辑正确。

## 6. 可访问性与键盘

- 9 个构筑格和 3 个技能都是可拖拽 `div`；
- `tabIndex=-1`，无 `role`，无 `aria-label`；
- 键盘不能聚焦或完成换位、升星、合成与技能释放；
- 只有 4 个原生按钮进入正常按钮语义。

结论：核心玩法缺少键盘和辅助技术入口。
