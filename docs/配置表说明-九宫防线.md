# 配置表说明 · 九宫防线（CONFIG 数据层）

> 对应代码：`geminicode.html` 顶部 `CONFIG` 对象 + `configLoader`
> 单一信息源：**改本配置即调参，无需动消费逻辑代码**
> 生效方式：修改后保存，刷新浏览器即生效
> 约束：单文件 HTML（R3），配置内嵌，无外部依赖

---

## 0. 这是什么 / 怎么用（先说人话）

这份配置就是游戏的「数值总账」。以前所有数字（第几波出多少怪、金币掉几个、建筑多重、老虎机抽中概率）都写死在代码各处，想改得翻源码找数字。现在全部集中到这一个地方：

- **想调难度** → 改 `waves`
- **想调钱多钱少** → 改 `economy`
- **想改建筑属性** → 改 `buildings`
- **想改抽奖概率** → 改 `slot_odds`
- **想改升星能力** → 改 `star_abilities`
- **想改排行榜算分** → 改 `score`

游戏启动时 `configLoader` 会自动检查这些配置有没有缺、合不合理，缺了用默认值并在浏览器控制台（F12）给出警告，不会让游戏崩溃。

## 2. CONFIG.waves —— 波次节点序列

单局从纯 9 波扩展为 **12 个节点**（保留原 9 波骨架 + 插入精英/资源/Boss 节点），单局约 15 分钟。

每个节点字段：

| 字段 | 类型 | 含义 | 约束 |
|---|---|---|---|
| id | number | 节点序号（1~12） | 唯一，递增 |
| type | string | 节点类型：`normal`普通 / `elite`精英 / `resource`资源 / `boss`终局 | 必填，四选一 |
| normal/fast/tanky/stealth | number | 各类敌人数量（缺省=0） | 非负整数 |
| boss | number | Boss 数量（0 或 1） | resource/boss 节点按需 |
| hpMult | number | 敌人血量难度系数（随节点递增） | >0，建议单调不减 |
| rewardBuild | number | 该节点奖励的 Build 次数 | 0~2 |
| bonusGold | number | 通关额外金币 | ≥0 |
| bonusCopper | number | 通关额外铜钱（资源波用） | ≥0 |
| note | string | 策划备注（不影响运行） | 可选 |

**调整方向**：
- 想拉长单局 → 增加 normal 节点数或提高 hpMult
- 想让玩家 Build 更多 → 提高 rewardBuild（注意同步提高难度，避免白送）
- 精英波(elite)是第一/二道检验关，建议 hpMult=1.5~1.75
- 资源波(resource)无战斗(normal:0)，靠 bonusCopper 补给经济

**观测指标**：单局实际时长（目标≈15min）、各节点通过率。

## 3. CONFIG.economy —— 双货币经济

分离 **铜钱（软货币，量大）** 与 **金币（硬货币，稀缺）** 两条管线。

### copper（铜钱）

| 字段 | 类型 | 含义 | 默认值 |
|---|---|---|---|
| initial | number | 开局铜钱 | 150 |
| perWaveBase | number | 每波基础结算铜钱 | 30 |
| killNormal | number | 击杀普通怪铜钱 | 3 |
| killBoss | number | 击杀 Boss 铜钱 | 70 |
| noLeakBonus | number | 完美防守（无泄漏）额外铜钱 | 15 |
| resourceWaveBonus | number | 资源波额外铜钱 | 200 |

### gold（金币）

| 字段 | 类型 | 含义 | 默认值 |
|---|---|---|---|
| initial | number | 开局金币 | 0 |
| perWaveBase | number | 每波基础结算金币 | 3 |
| killBoss | number | 击杀 Boss 金币 | 5 |
| noLeakBonus | number | 完美防守额外金币 | 5 |
| shopRefreshCost | number | 商店刷新成本 | 2 |
| investCost | number | 投资（老虎机能力）成本 | 3 |
| carryCap | number | 技能携带上限 | 4 |
| skillCapPerSkill | number | 单个技能携带上限 | 2 |

### spinCosts（刷新 Build 阶梯成本）

数组，索引 = `min(spinCount, len-1)`。默认 `[10,20,40,80,160]`。

**调整方向**：
- 金币太稀有 → 提高 perWaveBase / killBoss / noLeakBonus
- 想抑制无限刷新 → 提高 spinCosts 后半段
- 铜钱保证养成顺畅，可大胆投放；金币保持稀缺感

**观测指标**：玩家平均金币余额曲线、是否还觉得"金币卡脖子"。

## 4. CONFIG.buildings —— 建筑总表

每个建筑一个条目，key 为建筑 id。字段：

| 字段 | 类型 | 含义 | 必填 |
|---|---|---|---|
| id | string | 建筑唯一标识（与 key 一致） | ✅ |
| name | string | 显示名 | ✅ |
| icon | string | emoji 图标 | ✅ |
| tier | number | 阶位 1/2/3 | ✅ |
| school | string | 流派：`fire`火药 / `water`雷水（第三流派预留扩展） | ✅ |
| rarity | string | 稀有度：`common`/`uncommon`/`rare`/`epic`（影响排行榜计分） | 建议 |
| dmg | number | 基础伤害（辅助件=0） | ✅ |
| cd | number | 攻击冷却(ms) | 有 dmg 时必填 |
| range | number | 射程(屏幕比例) | 建议 |
| single | number | 1=单体 / 缺省=范围或特殊 | 可选 |
| aoe / chain / wet / lightning / pierce / fire / burn 等 | number | 特殊效果标志（见现有代码消费逻辑） | 按效果 |
| synergy | object | **协同加成**（价值三原则·协同是最优解放大器） | 可选 |
| selfBoom / selfRain | object | **自带独立价值**的能力（不依赖邻居触发） | 可选 |
| recipe | array | 合成产物配方（高阶件才有，[材料1,材料2]） | 高阶件 |
| trigger / trigDmg | string/number | 触发型被动（命中触发时的额外效果） | 可选 |
| desc | string | 描述文案（面向玩家） | ✅ |

**价值三原则（修正版）约束**（新增建筑必须遵守）：
1. **自带价值**：即使没邻居、不触发条件，也必须有独立战斗贡献（dmg / selfBoom / selfRain / 经济 至少占一）。
2. **协同是最优解放大器**：协同（synergy）只放大价值，不决定价值是否存在——不协同能用，协同则达最高性价比。
3. **成长闭环**：每个 T1 基础建筑必须有进阶路径（同名升星 OR 异类配方合成），不允许孤岛。

**第三流派预留**：`school` 字段允许新增枚举值（如 `ice`/`physical`），数据结构已留插槽，内容待用户定方向后填充。

## 6. CONFIG.slot_odds —— 老虎机权重与概率调节

| 字段 | 类型 | 含义 | 默认 |
|---|---|---|---|
| reel_base | object | 各建筑权重基值（**越低越稀有**） | archer/waterTower=14，其余 9~13 |
| tilt.strong | number | 强势流派倾斜系数（>1） | 1.15 |
| tilt.weak | number | 弱势流派压制系数（0~1） | 0.90 |
| tilt.triggerThreshold | number | 单流派达到此件数才触发倾斜 | 3 |
| antiStack.threshold | number | 反堆叠阈值（某建筑≥此数减半） | 4 |
| openingBoost.waves | number | 前 N 波保底 | 2 |
| openingBoost.archer/waterTower | number | 保底额外权重 | 6 |

**调整方向**：
- 某流派太垄断 → 降低 tilt.strong 或提高 triggerThreshold
- 某建筑太难抽 → 提高其 reel_base
- 想保留流派分化但不要太极端 → 收窄 strong/weak 差距（已从旧 1.4/0.75 收到 1.15/0.90）

**观测指标**：抽样 1000 局，任一 school 出场占比不应 >70%；各建筑实际出场率。

## 7. CONFIG.star_abilities —— 升星能力池

同名建筑升星获得特定能力。每条：

| 字段 | 类型 | 含义 |
|---|---|---|
| id | number | 能力 id（1~10） |
| name | string | 能力名 |
| desc | string | 描述（面向玩家 tip） |
| effectType | string | 效果类型枚举 |
| value | number | 数值 |

规则：每建筑最多 2 条不重复能力（分配规则见设计规格升星章节）。

## 8. CONFIG.score —— 排行榜计分系数

| 字段 | 类型 | 含义 | 默认 |
|---|---|---|---|
| rarityPoints | object | 各稀有度折算基础分 | common10/uncommon18/rare30/epic45 |
| starMultiplier | array | 星级倍率（index=star，0~5） | [1,1.5,2.0,2.8,3.6,4.4] |
| hpWeight | number | 剩余血量每点折算分数 | 20 |
| copperScoreDivisor | number | 每 N 铜钱折算 1 分 | 10 |
| goldWeight | number | 每金币折算分数 | 50 |

**总分公式**：`Σ(建筑 rarityPoints × starMultiplier[star]) + 剩余血量×hpWeight + ⌊铜钱/copperScoreDivisor⌋ + 金币×goldWeight`

## 9. 修改后如何验证

1. 保存 `geminicode.html`
2. 双击在浏览器打开（或刷新）
3. 开一局，观察行为是否符合预期（难度、钱、概率）
4. 若配置有误，按 F12 打开控制台会看到 `[CONFIG] xxx 缺失或非法` 警告
